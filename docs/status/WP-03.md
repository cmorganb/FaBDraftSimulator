# WP-03: Contracts + Python codegen

**Status:** DONE
**Date:** 2026-09-14

## What was built

- `contracts/*.schema.json`: `card`, `set`, `pack_config`, `draft_event`,
  `agent_view`, `pick_decision`, `decklist`, `session_config`. Fields match
  the plan's *simplified* contract shapes (sections 5.1-5.6, 6.3, 10) - this
  is the internal representation, not the raw upstream dataset shape; WP-01's
  ingestion script is responsible for mapping one to the other.
- `scripts/generate_contract_models.py`: shells out to
  `datamodel-code-generator` (pip-installable, no npm) with
  `--input contracts --input-file-type jsonschema`, resolving cross-file
  `$ref`s (e.g. `set.schema.json`'s `cards` array referencing
  `card.schema.json`) into package-relative imports. Writes pydantic v2
  models to `packages/core/fabdraft_core/contracts/generated/` and a hand
  -maintained-shape `contracts/__init__.py` that re-exports one stable class
  name per contract (`Card`, `SetSnapshot`, `PackConfig`, `DraftEvent`,
  `AgentView`, `PickDecision`, `Decklist`, `SessionConfig`).
- CI (`.github/workflows/ci.yml`, "Regenerate contracts and diff-check")
  reruns this script and `git diff --exit-code`s the output directory - the
  contracts gate (CI gate 7).
- `packages/core/tests/test_contracts.py`: schemas are well-formed Draft
  2020-12, cross-file `$ref`s actually resolve (validated against real
  instances, including a negative case), and - per section 5.6 - `AgentView`
  is asserted to have exactly the allowed top-level fields, every nested
  object schema sets `additionalProperties: false`, and no property name
  anywhere in the schema suggests another seat's identity/pool/pick.
- `packages/core/tests/test_generated_models.py`: the generated pydantic
  models accept the same instances the schemas accept and reject unknown
  fields (`extra='forbid'` on every generated model).

## Interfaces exposed

- `from fabdraft_core.contracts import Card, SetSnapshot, PackConfig,
  DraftEvent, AgentView, PickDecision, Decklist, SessionConfig`.
- `packages/core/tests/conftest.py`: `load_schema(name)` and the
  `schema_registry` fixture, for any future test (WP-02 etc.) that needs to
  validate an instance against a contract. This is test-only infrastructure,
  not a runtime part of `fabdraft_core` - the package itself does no
  filesystem I/O at import time (plan section 4.1 item 2).

## Decisions taken

- `payload` in `draft_event.schema.json` is a loose `object`
  (`additionalProperties: true`) rather than a discriminated union per event
  `type`. A full per-event payload schema is deferred to whichever of
  WP-07/WP-11 first needs to validate specific payload shapes precisely.
- `Card.cost` (and `power`) are typed as nullable integers, matching the
  plan's own example. The *real* upstream dataset allows variable costs
  ("X"), which this contract cannot represent yet - flagged as a known gap
  for WP-01/WP-02, not silently worked around.
- mypy needed `explicit_package_bases = true` and `mypy_path` set to the
  three implemented packages so that `tests/` (no `__init__.py`, per
  pytest's `--import-mode=importlib`) still resolves relative imports like
  `from .conftest import ...` under `mypy --strict`.

## Post-commit fix (discovered during WP-04)

The initial codegen invocation didn't pass `--disable-timestamp`, so every
regeneration rewrote each generated file's header comment
(`# timestamp: ...`) even with zero schema changes - the contracts-diff CI
gate (gate 7) would have failed on every single run. Fixed in
`scripts/generate_contract_models.py`; verified idempotent (two consecutive
regenerations now produce a byte-identical `contracts/generated/`).

## Amendment (WP-05, part 2): real IAR data required two more contract changes

Real Card Vault data for IAR (`data/IAR/`, gitignored) surfaced two more
gaps in `card.schema.json`, regenerated both times:

- **Added `object_type: enum["deck","arena","hero","token"]`** (required).
  `is_deck_card`/`is_arena_card` alone couldn't express that a hero must
  never appear in a pack *regardless of its own rarity* (real IAR's
  pre-release-only hero Baalghor is Marvel rarity) - see
  `fabdraft_core.packs.generator.is_pack_eligible` and
  `docs/status/WP-05.md`. `is_deck_card`/`is_arena_card` are now documented
  as derived conveniences (`object_type == "deck"` / `"arena"`) that are
  **not** complementary - a hero or token has both `false`.
- **Relaxed `pitch`** - removed its `enum: [1,2,3,null]` restriction. One
  real Fabled resource card has pitch `4`.

Every existing Card-constructing test (10+ files across `packages/core` and
`scripts`) needed `"object_type"` added to stay valid - a useful reminder
that a required-field contract change is a real-cost operation across the
whole codebase, not a one-file edit.

## Known limitations

- TypeScript codegen does not exist yet (blocked on npm, see ADR-0001).
  `apps/web`'s future setup must add a parallel generation step and update
  the CI `web` job to actually check it.
- `draft_event.schema.json`'s loose payload means malformed event payloads
  won't be caught by schema validation alone yet.
