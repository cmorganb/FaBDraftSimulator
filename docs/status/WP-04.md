# WP-04: Seeded RNG + event store

**Status:** DONE
**Date:** 2026-09-14

## What was built

- `packages/core/fabdraft_core/rng.py`: `SeededRng` (wraps `random.Random`)
  and `rng_for(seed, *path) -> SeededRng`, deriving a deterministic sub-RNG
  by sha256-hashing `seed + "|" + "|".join(path)` into an integer seed. Same
  seed+path always produces the same draw sequence, independent of what
  other `rng_for(...)` calls happened first (plan section 6.1) and
  independent of global `random` module state (verified by a test that
  reseeds the global module in between and checks output is unaffected).
  Exposes `choice`, `weighted_choice` (raises on empty/all-non-positive
  weights rather than picking arbitrarily), `shuffle` (returns a new list,
  never mutates its input).
- `packages/core/fabdraft_core/logs/jsonl.py`: `append_event`,
  `append_events`, `iter_events` (lazy), `read_events` for `DraftEvent`.
  Schema conformance comes for free from `DraftEvent` being a pydantic
  model (`extra="forbid"`) - there is nothing left to validate at
  serialization time.
- `packages/core/fabdraft_core/draft/events.py`: `EventStore` (in-memory,
  append-only, `.events` returns a defensive copy) and a standalone
  `fold(events, reducer, initial)` pure left-fold, generic over a `State`
  type parameter (PEP 695 syntax: `def fold[State](...)`). The real
  `DraftState` reducer is WP-07's; this WP proves the mechanism with a
  synthetic "count events by type" reducer in tests, including a Hypothesis
  property test that folding an arbitrary event sequence twice always
  yields identical state.
- 56 tests total across `test_rng.py`, `test_events.py`, `test_jsonl.py`
  (plus everything from WP-00/01/03); `packages/core` coverage is 99%.

## Interfaces exposed

- `fabdraft_core.rng.{SeededRng, rng_for}`
- `fabdraft_core.draft.events.{EventStore, fold, Reducer}`
- `fabdraft_core.logs.jsonl.{append_event, append_events, iter_events,
  read_events}`

## Decisions taken

- `fold`/`EventStore.fold` are generic (`State` type parameter) rather than
  tied to a concrete state type, since the real `DraftState` shape doesn't
  exist yet (WP-07). WP-07 should be able to plug its reducer straight in
  without changing this module.
- CI's purity grep (WP-00) was narrowed from `packages/core packages/agents`
  to `packages/core/fabdraft_core packages/agents/fabdraft_agents` so that
  `test_rng.py` can deliberately touch the global `random` module to prove
  `SeededRng` is isolated from it, without tripping the gate. The gate's
  intent (no hidden randomness in engine logic) is unaffected - test code
  was never what it was meant to police.

## Post-commit fix to WP-03

Found and fixed a bug in `scripts/generate_contract_models.py` while
verifying this WP's "no diff" expectations: missing `--disable-timestamp`
meant every codegen run rewrote a header timestamp even with no schema
changes, which would have broken CI gate 7 on every run. See
`docs/status/WP-03.md`'s "Post-commit fix" section.

## VERIFY items resolved or escalated

None - no game-rule logic in this WP.

## Known limitations

- No real `DraftState` reducer exists yet; `fold`'s determinism is proven
  generically, not against the actual draft state machine.
- `jsonl.py` re-reads and re-parses the whole file on every `read_events`
  call; fine for now, worth revisiting if WP-24 (batch analytics) needs to
  stream very large logs.
