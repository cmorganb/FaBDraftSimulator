# WP-05: Pack generator

**Status:** DONE
**Date:** 2026-09-14

## What was built

- `packages/core/fabdraft_core/packs/generator.py` (pure, deterministic):
  - `is_pack_eligible(card)` / `index_by_rarity(cards)` - decide which cards
    can appear in ANY pack slot at all. **This logic was corrected once real
    IAR data arrived - see "Amendment, part 2" below; the rest of this
    section describes the final, correct behavior.** A hero or token is
    excluded regardless of its own rarity; a Basic-rarity *arena* card (a
    young hero's own dedicated weapon/arm-equipment) is excluded; a
    Basic-rarity *deck* card is NOT excluded (real packs physically contain
    2 Basic-rarity deck-card slots, S7, even though neither is draftable,
    D5) - and neither is a non-Basic-rarity arena card (real Common/
    Legendary equipment is ordinary, draftable booster content).
  - `generate_pack(cards, pack_config, rng) -> Pack` - plan section 6.1's
    pseudocode, slot by slot in physical pack order, `rng.weighted_choice`
    per rarity draw, `rng.choice` among candidates, raising
    `PackGenerationError` (never silently relaxing) on pool exhaustion, an
    unrecognized rarity key, or a final card count that doesn't match
    `pack_config.pack_size`.
  - `Pack`/`PackedCard` dataclasses: a drafted instance's `draftable` flag
    comes from **the slot it was drawn from**, not `Card.draftable`'s
    static default - a rainbow-foil pull of what's normally a
    non-draftable-slot card is still draftable in that pack position,
    matching plan section 6.1's `instance(card, ..., draftable=slot.draftable)`.
  - Handles the chase slot's pseudo-rarity-keys (`M_expansion`, `CF`) from
    plan section 5.4's example config.
- `data/config/iar.pack_config.json` - the official IAR slot structure
  (plan S5/S7/S9), independent of whether real card data exists yet (this
  is a documented product fact, not data-dependent).

## Amendment, part 1 (to WP-01/WP-03, found while first implementing this WP)

Building this WP surfaced a real gap: nothing in the `Card` contract could
tell a core-subset Majestic apart from an expansion-slot one, which is
exactly what plan **S13** ("expansion majestics never appear in draftable
slots") requires the pack generator to enforce. Also found that
`scripts/ingest_set.py`'s `map_card()` hardcoded `draftable=False` for
every card and never looked at it - even though the real upstream schema
*does* carry this signal (`printings[].expansion_slot`, confirmed via the
same schema docs used in WP-01).

Fixed by adding a required `Card.is_expansion_slot: bool` field
(`contracts/card.schema.json`, regenerated) and a
`default_draftable(rarity, is_expansion_slot)` helper in
`scripts/ingest_set.py`, now used by both real ingestion (mapped from
`printings[].expansion_slot`) and `scripts/generate_fixture_set.py` (which
already knew which 20 of its 40 Majestics were "expansion" - it just wasn't
recording that fact on the `Card` itself). All existing Card-constructing
tests were updated for the new required field;
`data/fixtures/fixture_set.json` was regenerated. See the amendment notes
in `docs/status/WP-01.md` and `docs/status/WP-03.md`.

## Amendment, part 2: real IAR data proved the original exclusion rule wrong

The user provided a full Card Vault export of real IAR data at `data/IAR/`
(gitignored). Running the new `scripts/ingest_cardvault.py` (WP-01
amendment) and then this WP's `generate_pack` against it immediately failed:

```
PackGenerationError: slot 'basic': no candidates left for rarity key 'B'
```

The original `index_by_rarity` excluded **every** card with `is_deck_card`
false (i.e. every arena card, unconditionally) from the pack pool. Real
data showed this was wrong in two directions at once:

1. Real IAR has 17 "arena-card" (weapon/equipment) entries, but only 6 of
   them (the 3 young heroes' own weapon + arm-equipment) are Basic rarity
   and never drafted. The other 11 include **Common- and Legendary-rarity
   equipment that IS ordinary, draftable booster content** (e.g. "Robe of
   Repentance", a Common Shadow equipment piece was confirmed drawn into a
   `common` pack slot in a real-data test run). Blanket-excluding all arena
   cards silently made a whole category of real cards undraftable.
2. Real IAR's 2 heroes (Baalghor, Marvel rarity) and 1 token both needed to
   be excluded from packs *regardless of rarity*, which `is_arena_card`
   alone can't express - see WP-03's amendment adding `Card.object_type`.
3. Symmetrically, the 2 generic Basic-rarity **deck** cards in real IAR
   physically belong in the "basic"/"chase" pack slots (S7) even though
   they're never draftable (D5) - excluding *all* Basic-rarity cards from
   the pool (an intermediate fix attempt) broke pack generation entirely,
   since the "basic" slot then had nothing to draw from.

Final, correct rule (`is_pack_eligible`, see "What was built" above):
exclude `object_type in {"hero", "token"}` regardless of rarity, and
exclude `object_type == "arena" and rarity == "B"` - nothing else.
`scripts/generate_fixture_set.py` was updated to include two illustrative
non-Basic-rarity equipment cards (Common and Legendary) so this behavior
has fixture-level test coverage, not just a real-data manual check.

**Verified end-to-end against real data** (not just fixtures): ingested
`data/IAR/` → validated (refuses without `--allow-incomplete` due to 2
variable-cost/power cards, succeeds with it) → generated 1000 real packs,
every invariant held (16 cards, 14 draftable, no duplicate uids, no
expansion Majestic in a draftable slot, no hero/token ever drawn, Common
equipment correctly drawable).

## Decisions taken

- **S13 enforced structurally, not just by convention**: any slot with
  `draftable=True` automatically excludes expansion-slot Majestics from its
  candidate pool, regardless of whether `majestic_subset` is explicitly set
  to `"core"` - so a future config that adds a new draftable slot without
  remembering to set `majestic_subset` still can't violate S13.
  `majestic_subset: "expansion"` is honored explicitly for a non-draftable
  slot that wants only expansion Majestics (the `chase` slot uses the
  simpler `M_expansion` pseudo-key for this instead, but the explicit-field
  path is also supported and tested).
- Cold foil (`"CF"` pseudo-key) draws from the full deck-card pool
  regardless of rarity - this is a deliberate simplification of an already
  `confidence: ESTIMATED` slot, not a guess dressed up as fact.
- `generate_pack` takes `cards: list[Card]` rather than a full
  `SetSnapshot`, since only the card list is needed and this keeps the
  function trivially reusable/testable.

## Known limitations

- `iar.pack_config.json` has now been run against real IAR card data
  (1000 packs, see amendment part 2) - previously this said it hadn't.
- The rainbow-foil and rare-or-majestic slot weights remain
  `confidence: ESTIMATED` (plan S14/S15) - the statistical test checks the
  generator honors *whatever* weights are configured, not that those
  weights are correct; real card data can't resolve this (see above).
- `data/sets/IAR.json` (real ingested data) is gitignored and produced
  on-demand (`scripts/ingest_cardvault.py`) - it is data_integrity:
  incomplete (2 cards with unrepresentable variable cost/power) and must
  be loaded with `--allow-incomplete`.
