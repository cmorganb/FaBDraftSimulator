# WP-12: Replay

**Status:** DONE
**Date:** 2026-09-14

## What was built

- `packages/core/fabdraft_core/draft/replay.py` (pure engine logic; file I/O only in the golden-fixture script, same "injected port" precedent as `fabdraft_core.logs.jsonl`):
  - `RecordedPickSource`: a `fabdraft_core.draft.engine.PickSource` that replays previously-recorded decisions instead of deciding live. `run_draft` calls `get_pick` for a seat exactly once per `(round, pick_number)` in increasing order, so the Nth call corresponds to the Nth recorded pick for that seat - no need for `round`/`pick_number` as explicit arguments (the `PickSource` protocol doesn't pass them).
  - `recorded_pick_source_from_events(events) -> RecordedPickSource`: builds one from a log's own `PICK_MADE`/`PICK_AUTO` events.
  - `replay(original_events, cards, pack_config, *, session_id=None) -> tuple[DraftState, EventStore]`: extracts `seed`/`pod_size`/round count from the original log's `SEED_SET`/`POD_SEATED` events (raises `ReplayError` if either is missing - never infers a seed), builds a `RecordedPickSource`, and calls `run_draft` again to produce a fresh event log for comparison.
  - `events_match(a, b) -> bool` / `first_mismatch(a, b)`: byte-for-byte (well, field-for-field) comparison ignoring `ts_wall` (real wall-clock time, expected to differ between runs).
- `scripts/generate_golden_replay.py` + `data/fixtures/golden/fixture_draft_events.jsonl` (1063 events, committed): one full deterministic draft against `FIXTURE`, used as the golden regression fixture plan section 4.3 already names this directory for.
- 11 tests in `packages/core/tests/test_replay.py`, including the golden-file test itself.

## The real design problem this WP had to solve (not just "re-run and diff")

Naively feeding a recorded `picked_uid` back to `run_draft` as if it were a normal, on-time answer breaks replay for any pick that was originally a `PICK_AUTO` (timeout or invalid decision): the engine would see a valid on-time response and emit `PICK_MADE` instead of `PICK_AUTO`, changing the event log's shape - not a byte-for-byte replay at all. Caught this via a test using an `AlwaysTimesOutPickSource` original run, which failed until fixed.

**Fix:** `RecordedPickSource` tracks not just the recorded `picked_uid` but whether the original event was `PICK_AUTO` and, if so, its `reason`. On replay:
- a normal `PICK_MADE` entry replays its `picked_uid` directly;
- a `no_response` `PICK_AUTO` replays as `None` (a genuine decline);
- an `invalid_decision` `PICK_AUTO` replays as a sentinel string guaranteed not to be in any real pack.

In both `PICK_AUTO` cases, the engine's own `auto_pick` callable (`rng_for(seed, "autopick", round, pick_number, seat)`) re-derives the *same* uid deterministically, since the seed, round, pick_number, seat, and offered pack are all identical to the original run - reproducing the exact original `PICK_AUTO` event, not a different-looking `PICK_MADE`.

## Interfaces exposed

- `fabdraft_core.draft.replay.{RecordedPickSource, recorded_pick_source_from_events, replay, events_match, first_mismatch, ReplayError}`
- `data/fixtures/golden/fixture_draft_events.jsonl` - reusable by any future WP wanting a real, known-good event log fixture (e.g. WP-13's export tests, WP-17's CLI tests).

## Decisions taken

- Scoped to the **core mechanism only** - `apps/cli`'s actual `fabdraft replay runs/{id}` command is WP-17's job (that package is still an empty placeholder). `replay()` is exactly what such a command would call after loading `events.jsonl` from a `runs/{id}` directory.
- Chose real re-execution (`run_draft` + `RecordedPickSource`) over pure event-log folding (`fold_draft_events`, already built in WP-07) specifically because folding can't catch a determinism regression in the *generation* logic (pack sampling, shuffling, pass rotation) - it only ever replays already-recorded facts. This was a hard requirement from the acceptance criteria, not a style preference.
- `first_mismatch` exists alongside the boolean `events_match` specifically so a future CLI/debugging tool can report *where* two logs diverged, not just *that* they did.

## Known limitations

- The golden fixture is regenerated by re-running `scripts/generate_golden_replay.py`, which will silently produce a *different* (but still internally self-consistent) golden file if someone runs it after a legitimate engine change - the test only catches *unintended* drift between commits, not "did today's code match last month's." That's inherent to golden-file testing generally, not specific to this implementation.
- Replay assumes `pod_size` is constant across all rounds of a log (read once from `POD_SEATED`) - true for every session this codebase can currently produce (WP-07's engine takes one `pod_size` for the whole draft), but worth knowing if that ever changes.

## What the next WP needs to know

- WP-17 (CLI) should wire `fabdraft replay runs/{id}` to: load `events.jsonl` via `fabdraft_core.logs.jsonl.read_events`, call `fabdraft_core.draft.replay.replay(...)`, and report `events_match(...)` (plus `first_mismatch` on failure) to the user.
- `data/fixtures/golden/fixture_draft_events.jsonl` is a real, valid, complete draft event log - useful as a test fixture for WP-13 (exports) or WP-17 without needing to run a fresh draft in every test.
